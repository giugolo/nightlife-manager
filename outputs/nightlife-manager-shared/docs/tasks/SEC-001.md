# SEC-001 — riprodurre i confini tra organizzazioni negli emulatori

Stato: Ready, non implementato
Responsabile / reviewer: assegnare ai due soci prima di iniziare
Commit base: registrare dopo la pubblicazione del setup

## Risultato
Una suite automatica riproduce la lettura indebita tra due organizzazioni e distingue correttamente accesso consentito e accesso negato. Il task prepara prove affidabili per la successiva correzione delle Rules.

## Scope
Nuovi test Rules e relativo runner/configurazione, lockfile se serve un test SDK ufficiale. Consultare `firestore.rules`, `services/firestoreService.ts` e `types.ts`. Non modificare UI, modello dati o regole di produzione in questo task. Il responsabile prenota lockfile e runner prima del lavoro parallelo.

## Accettazione
- [ ] Due organizzazioni con admin e ospiti distinti; fixture solo fittizie.
- [ ] L'admin A può leggere gli ospiti A; il test positivo passa.
- [ ] L'admin B non dovrebbe leggere gli ospiti A; il test negativo fallisce con le Rules attuali, esponendo il difetto.
- [ ] Verificare anche query dei PR tra organizzazioni; annotare query esatte e risultati.
- [ ] Nuovo comando riproducibile senza login Firebase e senza backend live; prove del fallimento atteso conservate nella PR.

## Integrazione
Un test che espone un difetto noto non va aggiunto come check required su `main` lasciandolo rosso. Presentare questa PR come draft e integrarla insieme alla successiva correzione autorizzata, oppure tenere la riproduzione come comando diagnostico separato finché il fix non è pronto. Non trasformare il test in «expect allowed» per rendere verde la violazione.

## Evidenza
Audit locale sul commit originario `6a702ad`: admin di B poteva leggere ospiti e PR di A. Questo non è un test dello stato di produzione. Riprodurre nuovamente con la suite corrente prima di correggere.
